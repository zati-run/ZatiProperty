# Preserve ACLs during native schema authoring

Problem: pinned native fields.afterCreate automatically appends new fields to existing scoped role grants. Creating hierarchy relations therefore changed owner permissions without an explicit permission-generation step. Repairing grants afterward leaves an exposure window and cannot be the reusable construction contract.

Proposed reusable Loom companion: a typed additive field-authoring operation that runs the qualified native collection-manager field creation and its existing hooks inside one database transaction, while snapshotting affected ACL resource/action parameters. Preserve all pre-existing grants exactly by restoring only hook-added field entries before commit. Verify the full affected ACL projection equals its initial snapshot before returning. New authoring must not grant fields by default. Intentional role expansion remains a separately reviewed native role operation through Loom.

Qualify the exact installed hook source, transaction propagation, ACL table/model identity and cache invalidation behavior before implementation. Acquire deterministic locks on affected collection and permission rows; reject concurrent permission drift. Preserve pre-existing duplicate fields/order and all scopes, write grants, snippets and flags. Do not disable hooks globally, patch shared handlers per request, or blindly overwrite whole roles from a stale snapshot. If native hooks cannot participate atomically, fail closed and implement a qualified native hook extension before exposing the authoring operation.

The MCP contract needs schema/ACL baseline digests, expected native version/source pins, an explicit preserve-existing-access policy, durable command identity and read-only reconciliation for uncertain outcomes. Response must report field identity plus before/after ACL digest, never claim role acceptance solely from field creation. No arbitrary SQL or generic ACL override surface.

Qualification: field creation with owner/tenant/vendor scoped grants adds zero effective access; explicit subsequent manager grant works; concurrent role edit causes rollback; hook/reconciliation failure leaves neither field nor grant changes; lost response reconciles without replay; allowed/denied native reads and associations remain unchanged. Existing schema is preserved; the already-observed incident remains recorded rather than rewritten as an atomic operation.
